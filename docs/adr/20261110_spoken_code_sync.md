# ADR 0013: 電話機が読み上げる認証コードで同期し、電話機ごとの ID と鍵で認証する

## Status

Accepted

## Context

ADR 0010 は、アプリが Bluetooth LE で電話機と同期すると決めた。アプリはランプが光っている電話機を見つけ、Wi-Fi のネットワークとパスワードと、1 回だけ使えるトークンを渡す。

そのあと、モックが流れを変えた。家族はアプリで「同期を始める」を押し、電話機の受話器を上げて「＃」を押す。受話器が 6 桁の認証コードを読み上げ、家族はそれをアプリに入力する。作った電話機にあるのは、受話器、フック、呼び出し音、キーパッドである。ランプも、ほかのボタンもない。新しい流れは受話器とキーパッドだけでできる。

今は、すべての電話機が 1 つの合言葉を共有し、電話機は自分がどの見守る方のものかをバックエンドに伝える。合言葉を持っていれば、どの見守る方の電話機としてもつなげる。

新規登録では、モックは同期(L3)を、見守る方の名前を尋ねる画面(L6)より前に置く。家族が同期するとき、見守る方はまだいない。

この ADR は ADR 0010 の 3 つの決定を置き換える。Bluetooth LE での同期、Bluetooth LE での Wi-Fi の設定の受け渡し、アプリが電話機を通して渡す 1 回だけのトークンである。ADR 0010 が L4 と L5 に求めた変更も置き換える。ADR 0010 のほかの決定は残る。電話機は電話線も電話番号も持たない。見守る方 1 人に電話機は 1 台である。見守る方の設定(08)から同期すると、前の電話機を置き換える。新規登録では同期を済ませてから見守る方を登録する。ADR 0010 の Status は Accepted のままである。

ほかに次の案があった。

- アプリがコードを出し、家族が電話機のキーパッドで押す。モックは逆の向きを選んだ。アプリで入力するほうがキーパッドで押すより楽で、アプリは何がうまくいかなかったかを見せられる。
- 同期済みの電話機がいつでも「＃」に答える。この案では、家に入った人が電話機を自分のアカウントに結び付け、自分の伝言を AI に見守る方へ話させることができる。
- 同期でまず電話機を家族に結び付け、家族が見守る方を登録したときに、バックエンドが結び付きを見守る方に移す。この案では、結び付きを置く場所が 2 つになる。

## Decision

- 家族が「同期を始める」を押すと、バックエンドがその家族の同期の準備を始める。同期の準備は 10 分続く。
- 受話器が上がっているあいだに「＃」が押されると、電話機はバックエンドに認証コードを頼む。バックエンドは 6 桁の数字を作り、どの電話機に出したかを記録する。電話機はそれを 2 回読み上げる。
- 家族は認証コードをアプリに入力する。バックエンドは認証コードから電話機を見つけ、その家族の見守る方に結び付ける。受話器は、同期が完了したことを知らせる。
- 認証コードは 10 分有効である。有効なあいだに「＃」をもう一度押すと、同じ認証コードを読み上げる。認証コードを 5 回間違えると、同期の準備は終わる。1 人の家族が始められる同期の準備は、1 時間に 5 回である。
- 同期していない電話機はいつでも「＃」に答える。同期済みの電話機は、その見守る方の家族が同期の準備を始めているあいだだけ答え、その認証コードは、その見守る方の家族にだけ使える。
- アプリには結び付きを外すだけの操作を作らない。電話機を別の家族に渡すときは、チームが電話機の中の ID と鍵を消し、電話機は同期していない電話機として動き直す。
- 電話機は最初に起動したときに自分の ID と鍵を作ってファイルに残し、バックエンドに登録する。そのあとはその ID と鍵で認証し、バックエンドが結び付きから見守る方を決める。電話機は自分の見守る方を名乗らなくなる。共通の `PHONE_SECRET` は、電話機が登録するときの合言葉としてだけ残る。
- 新規登録では、同期が完了したときに、バックエンドが名前のない見守る方を作り、電話機を結び付ける。L6 はその見守る方に名前と呼び方を入れる。アプリは、見守る方がいない家族には L3 を、見守る方に名前がなければ L6 を、それ以外はホームを開く。
- バックエンドは同期の準備と認証コードをメモリーに置く。ADR 0011 の 1 つのインスタンスの上である。再起動すると消え、家族は始めからやり直す。
- 電話機は 1 回だけ作ってプログラムに埋め込んだ音声で話す。こうすると、インターネットにつながっていないことも話せる。
- 見守る方の家で家族が Wi-Fi をどう設定するかは、この ADR では決めない。当面は、人が Raspberry Pi Imager で設定する。
- アプリは L5 と 08 に電話番号を出さず、L3+ は電話線に触れない。これらの変更は、モックを作った方に頼む。

## Consequences

### Pros

- 流れがモックと合い、電話機にすでにある受話器とキーパッドだけを使う。
- アプリには Bluetooth のライブラリも Bluetooth の許可も要らず、電話機には BlueZ が要らない。アプリの Web 版でも同期できる。
- 認証コードを聞けるのは受話器を持っている人だけなので、同期できたことは、家族が電話機のそばにいることを示す。
- バックエンドが電話機の ID と鍵から見守る方を決めるので、電話機は別の見守る方の電話機としては動けない。
- 家に入った人は、同期済みの電話機を自分のアカウントに結び付けられない。
- 結び付きを置く場所は、見守る方の 1 か所である。

### Cons

- 家族は受話器で 6 桁の数字を聞いて入力する。聞き取れない家族は同期できない。
- 同期では Wi-Fi を設定しなくなる。電話機は同期の前にネットワークにつながっている必要があり、見守る方の家でそれをどうするかは決まっていない。
- L5 から L6 までのあいだ、名前のない見守る方がいる。見守る方を読むコードは、これを想定しなければならない。
- 電話機を別の家族に渡すには、チームの作業が要る。
- 登録するときの合言葉は、今もすべての電話機が共有する。1 台の電話機から合言葉を読んだ人は、自分の電話機を登録できる。その電話機も、家族がその認証コードを入力しないかぎり、結び付かない。
- 同期していない電話機は、家族が同期するまで、家にいる誰の「＃」にも答える。
- バックエンドを再起動すると、同期の準備と認証コードが消える。インスタンスを 2 つ以上にするには、それらを共有する場所が要る。
