# ADR 0005: issue とプルリクエストの書き方

## Status

Accepted

## Context

ADR 0004 では、issue、仕様書、プルリクエストの本文、コミットメッセージ、ADR を日本語で書くと決めた。プルリクエストの本文と仕様書は `yomiyasu` スキルで推敲し、チケットは推敲しないことも決めた。
人は、issue とプルリクエストを人が読みやすいものにしたいと考えている。ADR はすでに英語で書き、plamo-translate で訳してから、`yomiyasu` スキルで推敲している。
plamo-translate は意味の変わる訳をすることがある。ADR 0004 を訳したときは、「Checks and CI」という見出しを「小切手と信用状」と訳した。これは、金融の小切手と信用状という意味である。
プルリクエストの本文には、ファイルの木やコマンドの出力のようなコードブロックが入る。これらはそのまま残す必要がある。
この ADR は ADR 0004 のうち、issue、仕様書、プルリクエストの本文の書き方を決めた部分を置き換える。書き方についての ADR 0004 のほかの決定は変わらない。

## Decision

- 仕様書、チケット、プルリクエストの本文は、まず英語で書き、`mise run translate` で日本語に訳す。
- `mise run translate` は段落ごとに plamo-translate へ送る。コードブロック、ADR とプルリクエストのテンプレートの見出しと値、`Closes #12` のような行は、訳さずに残す。
- 仕様書とプルリクエストの本文は、訳したあとに英語と読み比べて誤訳を直し、`yomiyasu` スキルで推敲する。
- チケットは訳したあとに英語と読み比べて、誤訳だけを直す。`yomiyasu` スキルでは推敲しない。
- 仕様書とチケットの最後には、英語の原文を折りたたんだ `<details>` のブロックに入れて残す。プルリクエストの本文には英語の原文を入れない。
- コミットメッセージはこれまでどおり日本語で直接書く。
- 訳す前に、plamo-translate のサーバーが動いている必要がある。エージェントがサーバーにつながらないときは、作業を止めて人に知らせる。

## Consequences

### Pros

- 人は issue とプルリクエストを自然な日本語で読める。
- 実装役は仕様書とチケットの英語の原文も読めるので、誤訳に惑わされにくい。
- どのエージェントも同じコマンドで訳し、コードブロックは訳されない。

### Cons

- issue とプルリクエストを書くたびに、時間がかかる。
- plamo-translate のサーバーが、人の Mac で動いていることに頼る。
- チケットは `yomiyasu` スキルで推敲しないので、不自然な日本語が残ることがある。
- 仕様書とチケットは、英語の原文を入れる分だけ長くなる。
