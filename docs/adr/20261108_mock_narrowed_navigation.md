# ADR 0009: モックで機能を絞ったあとの画面の移り方とデモの動き

## Status

Accepted

## Context

PR #65 と #66 で、UI のモック `docs/mock/ui.html` が書き直された。モックは機能を減らし、一部の画面のつながり方を変えた。仕様書 #67 で、アプリをこのモックに合わせる。

前の 2 つの ADR には、新しいモックにはもうない動きが書いてある。

- ADR 0001 では、01、05、07 はタブバーを隠して全画面で開き、05 は開いた元の画面に戻って、もどるボタンのラベルは「もどる」にすると決めた。新しいモックの 05 はタブバーを出し、「通話記録」を開いているタブにして、もどるボタンで 04 に戻る。
- ADR 0002 では電話の最中をデモでどう見せるかを決めた。01 の「通話」を押すとホームが電話の最中になり、それは終わらない。`HOME_STATE` で電話の最中のホームと、電話に出なかったときのホームを開く。07b のボタンは 1 つである。予約の詳細は「準備中です」と出す。新しいモックには電話の最中の画面も「通話」のボタンもない。01 には「今すぐ通話」があり、押すと伝言への返答(01b)に移る。電話の最中は「今すぐ通話」を押せない(01a)。07b にはボタンがない。06b では予約を編集する。

アプリはまだ電話をかけられない。バックエンドには電話を始めるエンドポイントがなく、電話の最中であることや、見守る方が伝言に何と答えたかを知らせるものもない。

この ADR は ADR 0001 と ADR 0002 のこれらの部分を置き換える。2 つの ADR のほかの決定は変えない。

## Decision

- 05 は通話記録のタブの中で、タブバーと一緒に開く。もどるボタンは「通話記録にもどる」と読まれ、04 に戻る。ホームの「会話を見る」は通話記録のタブに切り替え、そこで 05 を開く。01 と 07 は今と同じく、タブバーのない全画面で開く。06b も同じである。
- 電話の最中のデモを消す。青い帯、電話の最中のホーム、`HOME_STATE=calling` である。`HOME_STATE=missedCall` は 07b を開くただ 1 つの方法として残す。
- 01 と 06b の「今すぐ通話」は、アプリが電話をかけられるようにする仕様書ができるまで、「準備中です」と出す。01a と 01b もその仕様書で作る。
- 07b にはモックのとおりボタンを置かない。
- 06b では 06 で選んだ予約を編集する。06b の「なおす」は 01 と同じく「準備中です」と出す。
- ホームの設定の歯車は、見守る方の設定(08)を作る仕様書ができるまで、「準備中です」と出す。

## Consequences

### Pros

- アプリの画面の移り方が新しいモックに合い、デモはモックで消えた動きを見せない。
- 家族は 05 からいつも通話記録に戻るので、タブバーで自分がどこにいるかが分かる。
- 電話の最中のデモを消すと、Firestore のデータを出すホームではもともと出せなかった状態がなくなる。

### Cons

- アプリが電話をかけられるようになるまで、デモでは「今すぐ通話」のあとに何が起きるかを見せられない。
- ホームから 05 を開いた家族は、もどるボタンではホームに戻れない。代わりにタブを切り替える。
- 設定の仕様書ができるまで、ホームの歯車を押しても役に立つことは起きない。
