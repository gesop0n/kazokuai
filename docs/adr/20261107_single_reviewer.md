# ADR 0006: レビュー役を Codex だけにする

## Status

Accepted

## Context

ADR 0004 では、Codex がすべてのチケットをレビューし、Claude Code が実装したチケットは Grok もレビューすると決めた。
チケット #19 では、Codex と Grok が同じ変更を `code-review` スキルでレビューした。
Codex は約 5 分で 4 つの問題を見つけ、そのすべてが直された。そのうち 3 つは電話の動きの不具合で、Codex はそのうち 2 つを一時的なテストで再現した。
Grok は約 15 分で 9 つの問題を見つけた。1 つは Codex の指摘と同じで、4 つは小さな整理、4 つは直さなかったものである。直さなかった 4 つのうち 2 つは、仕様書のコメントと Grok に渡した指示で、すでに答えが出ていた。
人はレビューにかかる時間を短くし、2 つのエージェントに同じことをレビューさせないようにしたいと考えた。
この ADR は ADR 0004 のうちレビュー役を決めた部分を置き換える。この決定は 1 つのチケットだけをもとにしている。

## Decision

- レビュー役は Codex だけにする。Codex は、どのエージェントが実装したチケットも、`code-review` スキルの 2 つの観点(書き方の決まりと仕様)でレビューする。
- ADR 0004 で決めたとおり、Grok は実装役のままにする。
- チケットをもっと回したあとに、`/retro` でこの決定を見直す。

## Consequences

### Pros

- チケットごとのレビューが早く終わる。
- 同じ指摘が 2 つのファイルに重ねて出ない。
- 実装役が扱う指摘のファイルは 1 つになる。

### Cons

- 変更をレビューするのが 1 つのモデルだけなので、Codex が見落としたものを、ほかのレビュー役が拾うことはない。
- この決定は 1 つのチケットだけをもとにしている。
