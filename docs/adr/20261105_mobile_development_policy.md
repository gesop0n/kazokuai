# ADR 0001: モバイルアプリの開発方針

## Status

Accepted

## Context

`docs/mock/ui.html` をもとに、`mobile/` のアプリを Flutter で作る。
`backend/` と `device/` はまだ空なので、通話、AI のまとめ、電話機との同期は実データで動かせない。
モックは 22 枚あるが、スクロールや状態の違いをまとめると 15 画面になる。

## Decision

### 全体

- 仮データで動くデモを先に仕上げる。本番化はその後に判断する。
- 普段は iOS で確認し、Android は Android Studio の導入後の手順から確認する。
- 対応言語は日本語のみとし、ロケールを `ja` に固定する。多言語化の仕組みは入れない。
- 端末の設定によらず、ライト表示に固定する。
- 色、文字、余白、角丸はモックに合わせ、動きは OS 標準に従う。ピクセル単位の一致は求めない。
- 文字サイズは OS の設定に 1.3 倍まで追従する。モックの固定の高さは、最小の高さとして扱う。
- パッケージ名は `kazokuai` とし、`lib/` を `app/`(起動と画面遷移)、`design/`(色、文字、部品)、`features/<機能>/`(各機能の画面とデータ)に分ける。
- Bundle ID は実機配布が必要になるまで変えない。CocoaPods は必要になるまで入れない。

### デザイン基盤

- 色と文字は固定の定数(`AppColors`、`AppTextStyles`)にする。`ThemeExtension` は使わず、`ThemeData` には Flutter 標準部品の既定値だけを設定する。
- 色と文字はアプリの画面で使うものだけを移す。名前は Foundations に揃え、足りない色は同じ規則で追加する。
  - 移さない文字スタイル: `.cap-l`、`.mono-l`
  - 移さない色: `state/ok`、`state/care`、`night/raised`
  - イラストの色と Google ロゴの色は、定数にせず SVG の中に書く
- 余白は数値で直接書き、角丸と影は各部品の中に持たせる。
- アプリは `MaterialApp` で構成し、部品の見た目はモックに合わせて作る。押したときは波紋を出さず、薄く色を重ねる。
- 部品は、その部品を使う画面の手順で作る。ホームの手順までに作るのは `.btn`、`.card`、`.nightcard`、`.pill`、`.iconbtn`、`.avatar`、`.field`、`.ai-tag` とタブバーで、`.chip` は通話記録の手順で作る。
- フォントは `google_fonts` を使わず、7 ファイル(圧縮前で 23.91MB)を同梱する。
  - Zen Maru Gothic 400、500、700、900
  - Shippori Mincho 500
  - DM Mono 400、500
- アイコンはモックの SVG 22 個をファイルにして、`flutter_svg` で表示する。未使用の `square` と `mail` は入れない。
- フォントの SIL OFL 1.1 と Lucide の ISC の本文を同梱し、`LicenseRegistry` に登録する。
- 部品一覧画面は `lib/main_gallery.dart` から起動し、`main.dart` からは読み込まない。

### 骨組み

- 画面遷移には `go_router` を使う。
- 手順 3 ではログイン後の 6 画面(ホーム、通話記録、予約電話、01、05、07)だけをつなぐ。ログイン前の 9 画面は、ログイン判定と一緒に手順 6 で追加する。
- タブバーはホーム、通話記録、予約電話だけに出し、タブごとにスクロール位置を保持する。01、05、07 はタブバーを隠して全画面で開く。
- 05 は開いた元の画面に戻り、ラベルは「もどる」にする。ホームの「通話記録を見る」はタブの切り替えにする。
- モックに遷移先がないボタンは、押すと「準備中です」と短く表示する。
- Android の戻るボタンは、`go_router` の既定の動きのままにする。

### ホーム

- 手順 4 では通常状態の 00/02/03 だけを作る。通話中(01b)と不在(07b)は手順 5 で作る。
- 通話が 1 件もない状態、引っ張って更新、読み込み中とエラーの表示はデモに含めない。
- 「AIに伝えてもらう」カードの入力欄と「通話」は 01 を開くだけとし、ホームからは発信しない。
- データはクラスとサンプルデータに分け、見守る方を `WatchedPerson`、通話を `Call`、AI のまとめを `CallSummary` と呼ぶ。
- サンプルの基準日時は 2026 年 11 月 5 日 10:24 に固定し、画面では端末の時計を使わない。
- 状態管理の Riverpod は操作で状態が変わり始める手順 5 で入れる。
- 7 日間のグラフは `Row` と `Column` で作る。
- モックの `aria-label` を `Semantics` に移し、押せる領域を 44pt 以上にする。

### 確認と PR

- PR は次の順に分ける。2 と 3、4 と 5 は並行して進める。
  1. 色、文字、フォント、アイコン
  2. 部品と部品一覧画面
  3. タブと画面遷移
  4. ホームの上半分(ヘッダー、直近の電話、AIに伝えてもらう)
  5. ホームの下半分(今日の様子、この 7 日間の電話)
- 見た目はシミュレーターのスクリーンショットをモックと見比べて確認する。
- 幅 360〜440、文字倍率 1.0 と 1.3 で崩れないことを Widget テストで確かめる。画像比較テストと CI は今は作らない。
- PR の説明文に「Flutter の要点」を 3 点まで書く。

## Consequences

### Pros

- バックエンドと電話機を待たずに、画面と操作を確かめられる。
- フォントを同梱するので、デモの場所の回線に表示が左右されない。
- アイコンがモックと同じ見た目になり、外部パッケージの改名の影響も受けない。
- 実際に使う部品だけを作るので、使わないコードが残りにくい。

### Cons

- サンプルデータでは、実データの遅延やエラーの扱いを確かめられない。
- フォントでアプリのサイズが増える。削減は配布前に検討する。
- アイコンを追加するときは、SVG を手で追加する必要がある。
- ダークモードや多言語化が必要になると、定数の持ち方と文言の管理を作り直すことになる。
