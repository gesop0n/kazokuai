# ADR 0003: デバイスおよびバックエンドのアーキテクチャ

## Status

Accepted

## Context

見守る方の家に置く Raspberry Pi(ラズパイ)が、Gemini Live API を通して見守る方と声で話す。ラズパイは Live API を直接呼ぶ。
`backend/` と `device/` はまだ空である。ADR 0002 では Gemini との接続をバックエンドと一緒に行うと決めた。
Live API は 1 つのセッションの中でしかコンテキストを持たない。前回の電話で聞いた膝の痛みについて尋ねるなど、AI に過去の電話を覚えさせるには、Live API の外に記憶を持つ必要がある。
Live API の音声だけのセッションは、コンテキストウィンドウの圧縮を有効にしないと約 15 分で終わる。モックには 31 分続く電話がある。
アプリにはまとめ、今日の様子、通話記録を出す。電話が終わるたびに内容をまとめる処理は、どのみち必要になる。
デバイスとバックエンドの言語として、Python、Go、Kotlin、Java、TypeScript、Dart、Rust を比べた。
バックエンドの HTTP 層について、標準の `net/http`、Gin、chi を比べた。

## Decision

### 全体

- ラズパイはトークンを受け取ること、電話の音声を Live API につなぐこと、文字起こしを送ることの 3 つだけをする。予約、かけなおし、記憶はバックエンドが扱う。
- バックエンドは Firebase と Cloud Run で動かす。
- デバイスとバックエンドは Go で書く。リポジトリの直下に置く 1 つの Go モジュールにまとめ、共通の型は `internal/protocol/` に置く。
- `mise.toml` に `go` を足す。

### 記憶

- 記憶は見守る方ごとに持つ。
- 電話の前に、バックエンドが記憶を短くまとめてシステム指示に書く。中身はプロフィール、見守る方が気にしていたこと、直近の電話のまとめ、今回の電話の目的(家族からの伝言など)の 4 つである。
- バックエンドは `LiveConnectConstraints` で、システム指示を短命トークン(ephemeral token)に固定する。ラズパイは API キーを持たず、プロンプトも組み立てない。
- AI は電話の途中で記憶を保存しない。例外は転倒のような急ぎの話だけである。その場合に備えて、家族に知らせるツールを関数呼び出し(function calling)でモデルに渡す。
- 電話が終わると、ラズパイが文字起こしをバックエンドに送る。バックエンドは Live API を使わずに Gemini を構造化出力で呼び、アプリ用のまとめと、記憶の変更(追加、更新、解決済みにする)の 2 つを一度に作る。
- 記憶はプロフィール、気にしていること(期限と状態つき)、出来事(どの電話で聞いたかつき)、直近のまとめ、話し方の 5 種類で持つ。
- 最初はベクトル検索を使わない。1 人分の記憶は小さいので、システム指示に収まる分を選び、それを全部渡す。記憶が収まらなくなったら、関数呼び出しで検索のツールを足すか、Vertex AI Memory Bank を検討する。
- モックの利用規約の第 2 条に従い、見守る方が同意するまでは記憶を作らない。
- 家族は、AI が覚えていることを見て消せる。まとめを直した内容は、記憶にも反映する。モックにはこれらの画面がないので、別に設計する。
- AI は健康についての記憶を、具合を尋ねるためだけに使い、判断や助言には使わない。この決まりはシステム指示に書く。

### Live API

- Gemini Developer API(ai.google.dev)を有料プランで使う。短命トークンはこの API のドキュメントで説明されている。無料プランでは、送ったデータが Google の製品の改善に使われる。
- 入力と出力の両方の音声で、文字起こしを有効にする。
- コンテキストウィンドウの圧縮と、セッションの再開を有効にする。
- モデルは実装を始めるときに、モデルの一覧と料金を確かめてから選ぶ。調べた資料では、モデルの名前と料金が食い違っていた。

### デバイス

- OS は Raspberry Pi OS Lite(64 ビット)にする。
- 使うライブラリは次のとおり。
  - Live API: `google.golang.org/genai`
  - 音声: `malgo`
  - ボタン、ランプ、フック: `go-gpiocdev`
  - バックエンドとの接続: `github.com/coder/websocket`
- プログラムは systemd で動かし、遠隔の保守には Tailscale を使う。
- 受話器の音声、フック、ランプ、呼び出し音はインターフェースで抽象化し、同じプログラムを Mac の内蔵のマイクとスピーカーでも動かせるようにする。
- デバイスのプログラムは実行ファイル 1 つで配布する。`malgo` は cgo を使うので、実行ファイルは arm64 の Docker 環境でビルドする。ラズパイの上では Docker を使わない。
- ラズパイはバックエンドと WebSocket でつなぎ続け、「今すぐかける」などの指示を受け取り、自分の状態を知らせる。

### バックエンド

- API は Cloud Run で動かし、chi(`github.com/go-chi/chi/v5`)で書く。リージョンは東京(asia-northeast1)にする。
- chi のハンドラは標準の `http.Handler` なので、`net/http` 向けのライブラリとミドルウェアをそのまま使える。Gin は、ハンドラが独自の型 `*gin.Context` を使うので採用しない。
- Firebase Auth(Google、メールアドレスとパスワード)、Firestore、FCM を使う。ライブラリは `firebase.google.com/go/v4` と `cloud.google.com/go/firestore` である。
- 電話が終わったあとの処理は Cloud Tasks から動かす。
- 予約とかけなおしは、1 分ごとに起動する Cloud Scheduler と Cloud Tasks で扱う。
- API キーは Secret Manager に置く。録音を短い間だけ残す場合は、自動で消すルールを付けて Cloud Storage に置く。
- アプリは Firestore を直接読み、家族ごとに見られる範囲をセキュリティルールで絞る。操作(今すぐ電話する、予約する、言い方の案を出す、AI の声を試しに聞く)は Cloud Run の API を通す。
- ラズパイへの指示は Firestore に書く。そのラズパイとの接続を持つ Cloud Run のインスタンスが指示を購読し、WebSocket で送る。
- バックエンドは接続の状態から、「電話機がオフライン」と「見守る方が電話に出なかった」を見分ける。
- 構造化出力では Go の構造体から JSON Schema を作り、`ResponseJsonSchema` に渡す。

### この ADR では決めないこと

- 電話機とラズパイのつなぎ方。案 A は専用の電話機で、受話器を USB オーディオでラズパイにつなぎ、フックとボタンを GPIO で読む。案 B は市販のアナログ電話機をアナログ電話アダプタ(ATA)でつなぐ。今は案 A が有力である。案 B にすると、SIP と、8 kHz から 16 kHz への変換が加わる。
- 見守る方の家で Wi-Fi を設定する方法と、アプリと電話機を同期する方法。Bluetooth を使うなら、ラズパイに BlueZ を、アプリに `flutter_blue_plus` を足す。
- 文字起こしの精度を上げるために、録音を短い間だけ残すかどうか。

## Consequences

### Pros

- ベクトルデータベースや別のサービスがなくても、AI が過去の話題を持ち出せる。
- アプリ用のまとめと記憶を同じ処理から作れる。
- ラズパイは API キーを持たない。プロンプトを変えるときは、バックエンドをデプロイするだけで済む。
- Go を使うので、配布は実行ファイル 1 つで済み、デバイスとバックエンドで同じ型を使える。
- 電話機のハードウェアができる前から、会話の作り込みを Mac で進められる。
- 電話機がオフラインのときと電話に出なかったときを見分けられるので、家族に誤って知らせることが起きにくい。

### Cons

- 記憶のまとめは短く保つ必要がある。記憶が増えると渡す分を選ぶ処理が要り、いずれは検索も要る。
- 記憶の抽出が間違うと、AI が間違ったことを話す可能性がある。家族が記憶を確かめて直す手段が要るが、その画面はまだ設計していない。
- `malgo` は cgo を使うので、ラズパイ向けの Docker でのビルドを用意する必要がある。
- 公式ドキュメントの例のほとんどは Python と JavaScript で書かれていて、Go では書き直す必要がある。
- 短命トークンと Live API の一部の機能は、安定版でない API のバージョンにあるので、変わる可能性がある。
- Cloud Run は WebSocket のリクエストを最長 60 分で終えるので、ラズパイはつなぎ直す必要がある。
- Firebase と Google Cloud に依存する。
