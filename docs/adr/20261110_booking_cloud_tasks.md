# ADR 0014: 予約ごとに Cloud Tasks のタスクを作ってかける

## Status

Accepted

## Context

ADR 0003 は、予約とかけなおしを、1 分ごとに起動する Cloud Scheduler と Cloud Tasks で扱うと決めた。どちらもまだない。ADR 0011 はハッカソンのあいだそれらを作らず、予約とかけなおしを作るときに足すとした。

今の予約は、アプリのメモリーの中にしかない。アプリはモックの見本の予約 3 件で始まり、2026 年 11 月 5 日を今日とし、新しい予約はページを読み込み直すと消える。予約した時刻になっても、何も電話をかけない。本当に電話をかけるのは、今すぐ通話だけである。

バックエンドは、最小 0 の 1 つの Cloud Run のインスタンスで動く(ADR 0011)。Cloud Run がインスタンスを 0 に縮めると、バックエンドの中のタイマーは止まる。そのため、何時間も先の予約をバックエンドの中で待つことはできない。

この ADR は、ADR 0003 の「予約とかけなおしは、1 分ごとに起動する Cloud Scheduler と Cloud Tasks で扱う」のうち、予約の部分だけを置き換える。かけなおしは、ここでは決めない。ADR 0003 の Status は Accepted のままである。

ほかに次の案があった。

- Cloud Scheduler が 1 分ごとにバックエンドを呼び、バックエンドが時刻の来た予約をかける。作るものは少ないが、電話が最大 1 分遅れ、予約がないときも毎分バックエンドが起きる。
- バックエンドの中のタイマー。インスタンスが 0 に縮むと止まる。

## Decision

- 家族がバックエンドの API で予約を保存するか直すと、バックエンドは見守る方の下の Firestore に予約を書き、その時刻の Cloud Tasks のタスクを作る。アプリは Firestore から予約を読み、書くのは API を通すときだけである。
- 予約は、直すたびに 1 つ増える番号を持つ。直すと番号が上がり、新しいタスクを作る。届いたタスクの番号が予約の今の番号と違えば、そのタスクは何もしない。
- タスクは、タスクのために作ったサービスアカウントの OIDC トークンを付けてバックエンドを呼ぶ。バックエンドは、電話をかける前にそのトークンを確かめる。
- タスクが届くと、バックエンドはトランザクションで予約に「かけた」印を付けてから、予約の伝えたいことと通話内容で、今すぐ通話と同じ電話をかける。同じタスクが 2 回届いても、かけるのは 1 回である。
- 電話機がつながっていないときや電話の最中のときは、バックエンドは、Cloud Tasks が 1 分おきに最大 10 分やり直すように答える。それでもかけられなければ、その電話は「つながらなかった」として残る。見守る方が出なければ「出なかった」として残る。かけなおしは、ここに含まない。
- 予約できるのは、今から 1 分より先、30 日先までである。Cloud Tasks は 30 日より先のタスクを作れないためである。1 人の見守る方に、10 分以内に近い 2 つの予約は置けない。
- Cloud Tasks のない `demo-` のプロジェクトでは、バックエンドの中のタイマーがタスクの代わりをする。

## Consequences

### Pros

- 電話は予約した時刻に始まり、最大 1 分遅れることはない。予約がないときは何も動かない。
- Cloud Run が 0 に縮んでいても、予約の時刻には電話がかかる。
- 待つこととやり直すことは Cloud Tasks が持つので、バックエンドはメモリーに予定を持たない。

### Cons

- 予約を直しても、古いタスクはその時刻までキューに残る。番号を確かめるので、そのタスクは電話をかけない。
- 予約できるのは 30 日先までである。
- タスクには、サービスアカウント、キュー、バックエンド自身の URL が設定として要り、Terraform がそれらを用意しなければならない。
- テストと手元ではタイマーを使い、Cloud Tasks を使わない。そのため、Cloud Tasks を通る道は本物のプロジェクトでしか確かめられない。
- かけなおしは、まだ設計がない。ADR 0003 の 1 分ごとの Cloud Scheduler は、あとの ADR で決めるまで、かけなおしのために残る。
